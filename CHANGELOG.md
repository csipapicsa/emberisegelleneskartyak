# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

The game has been live since April 2026; changes before this file are in the git history and in
[docs/worklogs/](docs/worklogs/).

## [Unreleased]

### Added
- Dependency lock files: `requirements.txt` and `requirements-dev.txt` are generated by pip-compile from
  `requirements*.in` and pin every package with hashes; CI fails when they drift, and pip-audit now checks
  exactly what gets installed. Dependabot opens weekly update PRs (pip, GitHub Actions, base image).
- Staging environment (`deploy/containers/`): rootless podman under a dedicated `eek` user, managed by
  systemd through Quadlet. It follows the `:main` image via `podman auto-update` and rolls back when the new
  container doesn't become healthy. nginx puts HTTPS and a password in front of it.
- Production container image (`Dockerfile`): non-root user, data in a `/data` volume, base image pinned by
  digest, health check. CI tests the image itself end to end and publishes it to GHCR on every merge to `main`.
- `/healthz`: 200 when the card database has a playable pack, 503 otherwise; reports the running commit.
- `EEK_DATA_DIR`: all runtime data (databases, generated PDFs) can live outside the code directory, the
  prerequisite for running the app in a container with a data volume. Default unchanged.
- End-to-end browser test (Playwright): three players create, join and play a round; runs as its own CI
  job and locally in the Playwright container (`scripts/e2e_in_container.sh`).
- Coverage gate in CI (branch coverage of `server/` and `scripts/`, minimum 75%), with a coverage table on
  each run's summary page.
- CI on GitHub Actions: lint (ruff), Python and JavaScript tests, gitleaks secret scan over the full history,
  pip-audit; documentation-only PRs skip the slow jobs; weekly scheduled run.
- `scripts/make_sample_db.py`: a card database with made-up cards, so a fresh clone and CI can run without the real
  card texts.
- GPL-3.0-or-later license, `pyproject.toml`, pinned `requirements.txt` and `requirements-dev.txt`.

### Security
- Production ran starlette 1.0.0 (5 known vulnerabilities) plus outdated anyio, certifi and idna, because
  only the direct dependencies were pinned. The lock file moves them to fixed versions.

### Changed
- Leftover room chat is wiped at app startup instead of at import time: importing `server.main` (as the tests
  do) used to delete the room chat of the live site's data directory. Tests now also redirect every
  writable database to a temp directory.
- `/admin/stats` takes the key as the HTTP Basic Auth password instead of a `?key=` URL parameter, so it no
  longer ends up in the nginx and uvicorn access logs or the browser history.
- The `/admin/stats` key comes from the `EEK_ADMIN_STATS_KEY` environment variable and the page stays closed
  without it (it was hardcoded).
- Deployment templates moved to `deploy/`; dated session notes moved to `docs/worklogs/`.
- English README with architecture, quickstart and test instructions.

### Removed
- Card content from the repository: `database/card_master.db`, the retired `cards.db` and its copies,
  `duplicate_cards.csv`, the SEO PDFs.
